1. What the code does

The Japan pipeline ingests domestic sales (国内向販売) from METI’s petroleum statistics workbooks (Excel), normalizes them to a long-form parquet database, and feeds notebooks/14_japan_demand_dashboard.ipynb.

METI XLS/XLSX → Raw cache → Parse (reference/japan.py) → Parquet → Dashboard

Layers

LayerRole
Scraper
scrapers/japan_meti.py		 Downloads 確報 monthly files, latest 速報, and 年報 editions from METI pages (via curl_cffi).
Reference
reference/japan.py		 Parsers for 速報 / 確報 / 年報; period labels (Reiwa/Heisei); JODI compare specs; seasonality helpers.
Processor
processors/japan_meti_consumption.py		 Maps product_native → product_canonical via reference/product_map.csv; writes parquet.
Update script
scripts/update_japan.py		 CLI: download → parse → upsert (routine) or full rebuild (bootstrap).
Notebook
notebooks/14_japan_demand_dashboard.ipynb		 Charts: headline total, seasonality, METI vs JODI, Kayrros jet. Reads parquet only.

Metric in the database: TOTDEMO (total domestic demand). Country code JP. Source id: japan_meti_domestic_sales.

2. METI publication types

Three tiers matter for this project. Filenames follow METI conventions.

JapaneseReadingTypical lagFile patternRole here
速報 sokuhō — preliminary flash ~M+1 h2j….xlsx under data/raw/japan/sokuhou/ Fast first estimate for the latest month; marked is_provisional=true until 確報 replaces it.
確報 kakuhō — final monthly ~M+2 seYYYYMMkakji.xlsx under data/raw/japan/kakuhou/ Authoritative monthly product tables (~15-month rolling window per file). Wins over 速報 and 年報 on overlaps.
年報 nenpō — annual yearbook Annual edition h2dhhpeYYYYk.xls / .xlsx under data/raw/japan/yearbook/ Long history (2007+ locally); fills years before 確報 window. Lower priority than 確報 when both exist.
Filename vs survey month se202603kakji.xlsx is the March 2026 edition of 確報, not “only March 2026 data”. Each file usually contains a rolling block of monthly rows (e.g. 2025-01 through 2026-03).

Charts (notebook)

  • Raw values are kL or tonnes as published.
  • Notebook converts to kbd using analytics.units.convert_series and per-product density kinds in reference/japan.py (UNITS_KIND).
  • Headline total includes all delivery products above, including naphtha (overall industrial + transport demand view).
Fuel-oil split (important) METI reports Ａ重油 and Ｂ・Ｃ重油 separately. In product_map.csv, Ａ重油 is Gasoil (distillate, compared with 軽油 vs JODI GASDIES), while Ｂ・Ｃ重油 is Fuel oil (residual, vs JODI RESFUEL). Do not sum them into one “fuel oil” series for JODI unless you mean heavy oil only (fuel_oil_bc).

5. How sources are merged

When building parquet from all local workbooks, duplicate (date, product_native) keys are resolved by priority:

  1. 確報 (kakuhou) — highest
  2. 年報 (yearbook)
  3. 速報 (sokuhou) — lowest; sets is_provisional until replaced

Within a single 確報 sheet, only the first domestic-sales table per product block is used (avoids a second table on the same sheet overwriting gasoline/gas oil with wrong scale).

6. How to update data (cookbook)

Run all commands from the country_oil_scraper/ folder:

cd country_oil_scraper

What do you want to do?

GoalCommandWhat happens
Monthly refresh (usual) 
python scripts/update_japan.py
 Downloads latest 速報 + last 6 確報 months (configurable with --lookback-months), parses only new/changed files, upserts into parquet.
Force re-download 
python scripts/update_japan.py --force
 Re-fetches METI files even if already cached.
Full rebuild from local files 
python scripts/update_japan.py --bootstrap --no-download
 Re-parses every .xlsx / .xls under data/raw/japan/ (yearbook + kakuhou + sokuhou). Use after parser fixes or adding yearbooks.
Bootstrap + download everything 
python scripts/update_japan.py --bootstrap
 Downloads 年報 (online where available), all 確報 links on index, latest 速報; full rebuild.
Reparse local only (no download) 
python scripts/update_japan.py --no-download --reparse-all
 Same full rebuild as bootstrap but never hits METI servers.
Manual file drop Save xlsx under kakuhou/ or yearbook/, then bootstrap with --no-download Parser picks up new files on next rebuild.
After any update Restart the Jupyter kernel and re-run notebooks/14_japan_demand_dashboard.ipynb from §1 Setup.

Log lines to expect

  • Rows : 2,7xx and Date range : 2007-01-01 -> … after a full rebuild with 2007–2024 yearbooks.
  • Provisional : 0 rows when 確報 has caught up to the latest months (速報 fully replaced).
  • Upsert: N replaced, M appended on routine refresh.

Also update JODI (for §5–§6 charts)

python scripts/update_jodi.py

JODI often lags METI by one or more months.

Tests

python -m pytest tests/test_japan_meti.py -q
