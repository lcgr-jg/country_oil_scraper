1. What the code does

The Korea pipeline automates product-by-product domestic petroleum consumption from KNOC/MOTIE via the public Petronet website (petronet.co.kr), menu 국내석유통계 → 국내소비 → 제품별소비 (program id KDCQ0200).

Petronet (HTML table) → Raw CSV bundles → Parse & normalize → Parquet database → Dashboard notebook

Layers

LayerRole
Scraper
scrapers/korea_knoc.py		 Downloads date ranges from Petronet, saves wide CSV files under data/raw/korea/.
Reference
reference/korea.py, reference/petronet_knoc.py		 Parses CSV/HTML, maps Korean/English columns to product_native, JODI compare specs, seasonality helpers.
Processor
processors/korea_knoc_consumption.py		 Builds canonical long-form table, upserts into korea_knoc_consumption.parquet.
Update script
scripts/update_korea.py		 CLI you run monthly: download → parse → save.
Notebook
notebooks/13_korea_demand_dashboard.ipynb		 Charts: seasonality, KNOC vs JODI, Kayrros jet, etc. Reads parquet only (no live scrape).

Historical bundles were bootstrapped once (~1997–present in ~5-year downloads). Routine updates are incremental: only newly fetched CSV files are parsed and merged.

PathDescription

3. Units and products

  • Native unit: kbpm — thousand barrels per calendar month (from Petronet table).
  • Charts: converted to kbd (thousand barrels per day) using days-in-month.
  • Products: 15 primary lines (gasoline, diesel, jet, naphtha, fuel-oil components, etc.). File “Total” is not summed with products.
  • JODI compare: uses flow TOTDEMO, unit KBD, country KR.

4. How to update data (cookbook)

Run all commands from the country_oil_scraper/ folder (project root):

cd country_oil_scraper

What do you want to do?

GoalCommandWhat happens
Monthly refresh (usual) 
python scripts/update_korea.py --force
 Re-downloads the recent bundle (제품별소비(202201-latest).csv), parses only that file, upserts into parquet. Also repairs any truncated historical CSV if detected.
Quick check (no network) 
python scripts/update_korea.py --no-download
 Skips download and parsing; parquet unchanged.
New month on Petronet, cache in the way 
python scripts/update_korea.py --force
 --force ignores “file already exists” and re-fetches.
Re-read all local CSVs into parquet 
python scripts/update_korea.py --no-download --reparse-all
 Parses every 제품별소비(*).csv; does not hit Petronet.
Full history re-download 
python scripts/update_korea.py --bootstrap
 Downloads 1997→present in ~5-year chunks; rebuilds parquet from all bundles.
Fix a broken / truncated CSV 
python scripts/update_korea.py --repair-gaps
 Finds bundles whose filename range doesn’t match months inside the file; re-downloads and incremental parse.
Manual CSV drop Save file under data/raw/korea/, then
python scripts/update_korea.py --no-download --reparse-all
 Or name it as a new bundle and use --reparse-all if it overlaps existing keys.
After any update Re-run (or restart kernel and run) notebooks/13_korea_demand_dashboard.ipynb so charts load the new parquet.

Log messages to watch for

  • Incremental parse (1 file(s)): 제품별소비(...).csv — only that bundle was parsed.
  • Upsert: N replaced, M appended — rows updated in parquet.
  • No new downloads and no --reparse-all; parquet unchanged. — nothing to do.
  • Missing months in stitched series — run --repair-gaps.

Also update JODI (for §7 charts)

python scripts/update_jodi.py

JODI often lags KNOC by one month; April KNOC may not have April JODI yet.

6. Naphtha vs headline demand

Naphtha is ~40–50% of Petronet’s file total but is mostly petrochemical feedstock, not transport demand. Headline charts (§2, §3, §5) exclude it so trends stay comparable to Thailand/Australia-style end-use views.

  • Naphtha is in the parquet and in seasonality + JODI (like India PPAC).
  • JODI product code: NAPHTHA (not used for Thailand/Australia — they don’t report it the same way).

8. Troubleshooting

SymptomLikely causeAction
Gap in charts (e.g. 2016–2018) Truncated manual CSV python scripts/update_korea.py --repair-gaps
Notebook shows old data Kernel not refreshed Restart kernel; re-run from §1
No new month after update Cached CSV without --force python scripts/update_korea.py --force
KNOC April but no JODI April JODI publication lag Update JODI later; compare through last common month
Duplicate months after overlap files Two bundles same period (e.g. 202301 + 202201) Delete redundant bundle or --reparse-all

9. Future automation (email / multi-country)

Not built yet, but the intended pattern is:

  1. Scheduled job runs update_korea.py --force (and other countries’ scripts).
  2. Compare parquet max(date) before vs after; collect gap warnings.
  3. Send one email summary: country, success/fail, new months, rows changed.

Korea incremental design already avoids re-parsing full history each run — suitable for a nightly or monthly cron task.
