1. What the code does

The Hungary pipeline ingests monthly petroleum statistics from MEKH (Hungarian Energy and Public Utility Regulatory Authority) via the public portal MEKH TAB (stattab.mekh.hu).

The web UI is an Angular + DevExtreme app backed by a public OData v4 API — not a Power BI export. The scraper calls OData directly; manual Excel downloads from the portal are optional for validation only.

OData API → JSON cache → Roll up products → Parquet → Dashboard

Why OData instead of Excel? The portal can export Excel, but OData returns the full history in one automated pull. Pagination uses $skip (5,000-row pages; no reliable @odata.nextLink).

3. Demand vs stocks flows

MEKH publishes IEA-style balance tables. We store only the rows that map cleanly to JODI-style demand and closing stocks — not the full balance (imports, refinery output, etc.).

DatasetOData entityFlow codeEnglish labelmetric_type
Demand HaviOlajMerleg GDINCTRO Gross inland deliveries (Observed) TOTDEMO
Closing stocks HaviOlajKeszlet CSNATTER Closing stock — national territory CLOSTLV
Do not sum all CS* stock locations MEKH splits closing stocks by territory (national, pipeline, holders, abroad, …). Summing detail locations double-counts. CSNATTER alone matches JODI CLOSTLV for Hungary within rounding.

Bio / non-bio rollups

OData returns leaf codes such as NONBIOGASO + BIOGASOL. The parser rolls these into Excel-style aggregate natives (e.g. Total motor gasoline) before writing parquet.

6. How to update data (cookbook)

Run all commands from the country_oil_scraper/ folder:

cd country_oil_scraper
GoalCommandWhat happens
First-time setup 
python scripts/update_hungary.py --bootstrap
 Downloads demand + stocks OData; builds parquet from scratch.
Monthly refresh 
python scripts/update_hungary.py
 Uses cached JSON if present; upserts into parquet. Use --force to re-fetch OData.
Force re-download 
python scripts/update_hungary.py --force
 Refreshes both OData snapshots from MEKH.
Offline re-parse 
python scripts/update_hungary.py --bootstrap --no-download
 Rebuilds parquet from local JSON caches only.
After any update Restart the notebook kernel and re-run from §1 in notebooks/22_hungary_demand_dashboard.ipynb.

Typical log output

Built 3,038 rows, 2008-01-01 -> 2026-03-01, metrics=['CLOSTLV', 'TOTDEMO'], products=9

Also update JODI (for comparison charts)

python scripts/update_jodi.py

Tests

python -m pytest tests/test_hungary_mekh.py -q

Tests hit live OData for demand/stocks fetch (requires network).

8. JODI and Kayrros comparisons

JODI

  • Country code: HU
  • Demand flow: TOTDEMO — compare panels in reference/hungary.py (JODI_COMPARE_SERIES)
  • Stocks flow: CLOSTLV — same panel definitions
  • LPG panel sums MEKH Natural gas liquids + LPG for JODI compare only
  • Others panel sums petcoke + other products (maps to JODI ONONSPEC)

Kayrros jet fuel

Requires kayros/jet_fuel/data/jet_fuel.duckdb (sibling repo to country_oil_scraper). Uses ISO country code HU. Kayrros measures in-flight burn; MEKH reports product deliveries — expect level differences, useful for direction and month-to-month changes.

10. Troubleshooting

ValueError: No bbl/tonne factor for product_kind=...

Every product_native must appear in reference/hungary.py → UNITS_KIND with a key from analytics/units.py::BBL_PER_TONNE (e.g. diesel, not distillate).

OData returns 400 on filter

MEKH rejects some $filter syntax (e.g. dimension_1 eq 'GDINCTRO'). The scraper uses startswith(dimension_1,'…') instead.

Partial OData download (~5,000 rows)

If row counts look truncated, check that fetch_odata_rows paginates with increasing $skip. Stocks need ~10k rows across all months.

JODI vs MEKH level gaps

  • Naphtha demand: MEKH GID can exceed JODI if petrochemical deliveries are treated differently.
  • Jet fuel vs Kayrros: MEKH includes domestic aviation deliveries; Kayrros is departure-country flight burn.
  • Timing: JODI often lags MEKH by one month.

Kayrros section skipped

Build or update the DuckDB under ../kayros/jet_fuel/data/jet_fuel.duckdb from the kayros jet_fuel project. Install duckdb in the notebook kernel env.
